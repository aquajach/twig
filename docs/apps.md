# App Specifications

The game UI presents three apps inside a WinUI3-themed desktop shell. Apps are accessed from the taskbar and render fullscreen (one at a time), matching the touch-first iPad form factor.

## Window Manager

### Model

Apps exist in one of two states: **active** (fullscreen, visible) or **minimized** (hidden). Only one app can be active at a time. Tapping a taskbar icon switches to that app or re-opens a minimized one.

### State (`useWindowStore`)

```typescript
type WindowState = {
  activeApp: AppId | null
  openApp: (app: AppId) => void
  minimizeApp: () => void
}
```

### Taskbar

Fixed at the bottom of the screen. Always visible, even when an app is active.

| Element | Behavior |
|---|---|
| App icon | Tap to switch to app. Highlighted when active. |
| Notification badge | Red dot or count, shown when app has unread activity. |

Layout: centered row of 3 icons with labels. Height ~60px to accommodate touch targets (minimum 44x44pt per Apple HIG).

### Transitions

App switching uses a simple crossfade or slide animation (CSS transition, ~200ms). No complex window management — the fullscreen constraint eliminates drag, resize, snap, and z-ordering concerns.

## WeTalk

Workplace instant messaging app. Primary interface for NPC conversations.

### Views

WeTalk has two views, rendered side-by-side on iPad landscape or as a navigable stack:

1. **Contact List** — left panel
2. **Chat View** — right panel (shown when a contact is selected)

On iPad in landscape, both panels are visible simultaneously (split view). The contact list takes ~320px, the chat view fills the rest.

### Contact List

A scrollable list of NPC contacts.

Each contact row shows:
- **Avatar** — circular, 40px, with initials or icon
- **Name** — bold, e.g. "Sarah Chen"
- **Title** — muted, e.g. "Senior Product Owner"
- **Last message preview** — truncated single line
- **Unread indicator** — blue dot or badge count
- **Locked state** — grayed out with lock icon for NPCs not yet unlocked by the storyline engine

Locked contacts are visible but not tappable. They become tappable when unlocked via `unlock_npc` side effect.

Contacts are sorted: unread first, then by most recent message.

### Chat View

Standard messaging UI for conversation with the selected NPC.

#### Message List

- Scrollable message area, newest at bottom
- Player messages right-aligned (accent color bubble)
- NPC messages left-aligned (neutral color bubble)
- Timestamps shown between message groups (relative: "just now", "2m ago")
- Typing indicator shown while waiting for AI response (three animated dots)
- Auto-scroll to newest message on new content

#### Suggested Replies

Two pill-shaped buttons displayed above the input field after each NPC message. Generated by a lightweight AI call.

```
┌─────────────────────────────────────────┐
│  💬 NPC: "Can you check the login page  │
│   and tell me the error code?"          │
│                                         │
│  ┌─────────────────┐ ┌───────────────┐  │
│  │ Sure, checking  │ │ Which URL?    │  │
│  │ now             │ │               │  │
│  └─────────────────┘ └───────────────┘  │
│                                         │
│  ┌─────────────────────────────┐ ┌───┐  │
│  │ Type a message...           │ │ ▶ │  │
│  └─────────────────────────────┘ └───┘  │
└─────────────────────────────────────────┘
```

Tapping a suggested reply sends it as if the player typed it. Both suggestions disappear after one is chosen or the player types a custom message.

Suggested replies are **not** shown:
- While the AI is still responding
- When the most recent message is from the player
- For the very first message in a conversation (NPC speaks first via storyline effect)

#### Chat Input

- Text field with send button
- Send on Enter (with Shift+Enter for newline on external keyboard)
- Disabled while AI is responding
- Placeholder: "Type a message..."

### Notification System

When the engine executes a `send_npc_message` side effect or an NPC replies while WeTalk is minimized:

1. Taskbar WeTalk icon shows notification badge (unread count)
2. A toast notification slides in from the top for 3 seconds showing sender name and preview

### Chat Persistence

All chat histories are stored in `useChatStore`, keyed by NPC ID. Messages persist across app switches and page reloads via localStorage.

## Browser

Mocked web browser app for interacting with in-game websites.

### Toolbar

A simplified browser chrome at the top of the app:

```
┌───┬───┬──────────────────────────────────┐
│ ⌂ │ ↻ │  Lion Bank E-Banking (TEST)      │
└───┴───┴──────────────────────────────────┘
```

| Button | Behavior |
|---|---|
| Home (⌂) | Navigate to Quick Access screen |
| Reload (↻) | Reset the current mocked webapp to its initial state |
| Address bar | Read-only. Shows the name of the current page. Not editable. |

### Quick Access

The home/landing page of the browser. Shows a grid of site tiles the player can visit.

```
┌─────────────────────────────────────────┐
│           Quick Access                  │
│                                         │
│  ┌──────────┐  ┌──────────┐            │
│  │  🏦      │  │  📋      │            │
│  │  Lion    │  │  (more   │            │
│  │  Bank    │  │  sites   │            │
│  │  E-Bank  │  │  TBD)    │            │
│  └──────────┘  └──────────┘            │
│                                         │
└─────────────────────────────────────────┘
```

Tiles are unlocked progressively by storyline side effects. Initially only "Lion Bank E-Banking (TEST)" is available.

### Mocked Webapp System

Each "website" in the browser is a React component registered with a `pageId`. The browser renders the component matching the current `pageId`.

```typescript
type MockedPage = {
  id: string
  title: string              // shown in address bar
  icon: string               // shown on Quick Access tile
  component: React.ComponentType<MockedPageProps>
  initialState: Record<string, unknown>
}

type MockedPageProps = {
  state: Record<string, unknown>
  dispatch: (actionId: string, payload?: unknown) => void
}
```

The `dispatch` function allows the mocked page to emit actions that the game engine can listen for via `browser_action` triggers.

The `state` is managed per-page in the game store. The engine can mutate it via `update_browser_page_state` side effects (e.g., changing the e-banking login form from "error" to "success" state after the developer "fixes" it).

### Lion Bank E-Banking Mock

The first (and initially only) website available.

#### States

| State | UI |
|---|---|
| `login` | Login form with username/password fields and submit button |
| `login-error` | Login form with red error banner: "Login failed. Error code: ERR-LB-4012" |
| `login-success` | Welcome screen: "Welcome, Test User. You are now logged in." |

State transitions:
- Initial state: `login`
- Submit with any credentials → `login-error` (until developer fixes it)
- After developer fix (engine updates page state) → submit transitions to `login-success`

The error code (`ERR-LB-4012`) is significant — the player needs to communicate it to the developer NPC to advance the storyline.

## Mission Center

Game progress tracker styled as a note/task management app.

### Tab Bar

Two tabs at the top of the app:

| Tab | Content |
|---|---|
| **Tasks** | Todo list of game objectives |
| **Memos** | Achievements and collectibles |

### Tasks Tab

#### Progress Bar

A horizontal progress bar at the top showing overall completion:

```
Tasks: 2/7 completed (29%)
████████░░░░░░░░░░░░░░░░░░
```

Percentage is calculated from all tasks across all storylines (both discovered and hidden). Only discovered tasks count toward the denominator shown to the player, but the actual total includes hidden tasks to prevent the player from knowing the exact scope.

**Correction:** The denominator shown to the player is the count of *discovered* tasks, so the percentage reflects progress among known objectives. As hidden tasks are revealed, the bar may appear to "decrease" — this is intentional and creates a sense of expanding scope.

#### Task List

Grouped by storyline. Each group has a storyline title header and a list of tasks beneath.

```
┌─────────────────────────────────────────┐
│  Tasks: 2/3 completed (67%)            │
│  ██████████████████░░░░░░░░░            │
│                                         │
│  E-Banking Login Bug                    │
│  ✅ Investigate the login error         │
│  ✅ Report error code to developer      │
│  ☐  Verify the fix works               │
│                                         │
│  (other storylines appear as they       │
│   are discovered)                       │
└─────────────────────────────────────────┘
```

Task states:
- **Hidden** — not rendered at all. Player doesn't know it exists.
- **Active** — shown with empty checkbox. Current objective.
- **Completed** — shown with checkmark. Struck through or muted.

Tasks cannot be manually toggled. They are completed only by the engine via `complete_task` side effects.

### Memos Tab

A grid of achievement/collectable cards.

```
┌─────────────────────────────────────────┐
│  Memos                                  │
│                                         │
│  ┌──────────┐  ┌──────────┐            │
│  │  🎓      │  │  🔒      │            │
│  │  First   │  │  ???     │            │
│  │  Day     │  │          │            │
│  └──────────┘  └──────────┘            │
│                                         │
└─────────────────────────────────────────┘
```

- Collected memos show their icon, title, and description on tap
- Uncollected memos are shown as locked placeholders (optional — could also be fully hidden)
- Memos are granted by `grant_memo` side effects
